**This is placeholder text, not photography instruction.** It exists so the lesson
template can be reviewed end to end — headings, contents list, callouts, tables,
figures, takeaways and questions — before any real writing begins.

## How this page is put together

The lesson title, description, difficulty and dates all come from frontmatter
rather than from the body, so they can be rendered in the page header, in listings
and in structured data without being parsed out of the prose.

Everything below this point is ordinary MDX. Paragraphs, lists and emphasis behave
as you would expect, and the measure is capped at around 68 characters so lines
stay comfortable to read on a wide screen.

### Headings become anchors

Every heading gets an id, generated with the same slugger that builds the contents
list on the right. That means a contents entry can never point at an anchor that
does not exist, and readers can link directly to a section.

<Callout type="tip">
  Callouts are for asides that would interrupt the flow if left inline. The label is real text
  rather than an icon, so it still carries meaning when read aloud.
</Callout>

## Tables and reference material

Tables come from GitHub-flavoured markdown. Numbers are set in tabular figures so
columns line up, and a wide table scrolls inside its own box rather than pushing
the page sideways.

  Markdown image syntax is deliberately rejected by the pipeline. Use the `Figure` component
  instead, which requires alt text and real dimensions.
</Callout>

### Longer sections

A third heading level is available and appears indented in the contents list. Two
levels are enough for a lesson; anything deeper usually means the page should be
split into two.

The contents list only renders when a lesson has three or more headings, so short
lessons are not given a sidebar that says almost nothing.

## What to do with this file

Delete it. It is committed so the template has something to render during review,
and so the schema, the loader and the page have a fixture to be tested against.

<KeyTakeaways>

- Frontmatter drives everything the page needs to know about itself.
- Reading time and the contents list are derived, never authored.
- Images go through `Figure` so alt text cannot be forgotten.
- Invalid frontmatter fails the build rather than shipping.

</KeyTakeaways>
